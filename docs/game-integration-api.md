# Game Integration API v1

Every game that wants to sell items through the Player Store implements this API.
The platform is the only caller.

This document is maintained by the platform team and is what we hand to a game
team when an integration starts. It has been through three integrations so far.

Base path: `/game/v1`

---

## `GET /game/v1/health`

```json
{ "status": "ok" }
```

---

## `GET /game/v1/players/{playerId}`

Returns the player as the game knows them.

```json
{ "playerId": "p-1001", "displayName": "Aino", "level": 12 }
```

Returns `404` with an error body when the game has no such player.

---

## `GET /game/v1/players/{playerId}/inventory`

What the player currently owns as a result of store purchases.

```json
{
  "playerId": "p-1001",
  "items": [
    { "itemId": "gems_small", "quantity": 1 }
  ]
}
```

Revoked grants are excluded.

---

## `GET /game/v1/catalog?playerId={playerId}`

The items this player can buy right now. Games are expected to filter out
anything the player is not eligible for, so that the store never shows an offer
that cannot be delivered.

```json
{
  "items": [
    {
      "itemId": "gems_small",
      "name": "Small Gem Pack",
      "priceMinor": 499,
      "currency": "EUR"
    }
  ]
}
```

**Item identifiers** are lowercase, `snake_case`, and stable for the lifetime of
the integration.

**Prices** are integer minor units in `priceMinor`, with an ISO 4217 code in
`currency`.

---

## `POST /game/v1/grants`

Delivers an item to a player. This is the call that moves value, so it is the
one we care most about.

Request:

```json
{
  "grantId": "0b3f...",
  "playerId": "p-1001",
  "itemId": "gems_small",
  "quantity": 1
}
```

Response `201`:

```json
{
  "grantId": "0b3f...",
  "playerId": "p-1001",
  "itemId": "gems_small",
  "quantity": 1,
  "status": "granted",
  "grantedAt": "2026-02-11T09:14:22Z"
}
```

**Idempotency.** `grantId` is generated by the platform and is the idempotency
key. A repeated call with the same `grantId` must not deliver the item a second
time; it returns `200` with the original grant. Networks fail and we retry, so
this is a hard requirement rather than a nicety.

**Synchronous.** The response reflects the final outcome. When the platform gets
a success it treats the item as delivered.

---

## `GET /game/v1/grants/{grantId}`

Returns a previously created grant, `404` when there is none.

---

## `POST /game/v1/grants/{grantId}/revoke`

Reverses a grant, for refunds and chargebacks. Returns `200` with
`"status": "revoked"`.

Required. A player who has been refunded must not keep the item.

---

## Errors

Failures use an HTTP status that reflects the problem, with:

```json
{ "error": "some_code" }
```

| Status | When                                        |
|--------|---------------------------------------------|
| `400`  | The request is malformed                    |
| `404`  | The player, grant or item does not exist    |
| `422`  | Understood, but cannot be fulfilled         |
| `5xx`  | The game failed. The platform may retry.    |

A `2xx` status means the call succeeded.

---

## Timing

The platform allows **2 seconds** per call before it gives up and retries.

---

## Before going live

An integration is enabled for players once the game team confirms the endpoints
above are implemented and the platform team has run a purchase through in a
non-production environment.
